# Decoder-only input boundary

2026-10-04 UTC. **CANDIDATE experiment**, not a production preview capability.
The generator and decoder now run as separate executables. The decoder receives
bounded caller-supplied bytes on stdin; it no longer generates/encodes its own
fixture before decoding. All tests in this change supply generated fixture data.
It accepts no file path, provider selection or command argument. Lack of a path
argument is not filesystem/network confinement; no runtime sandbox is claimed.

## Source separation and ownership

`jpeg_decode.cpp` now owns the existing scale/decode/EXIF/orientation procedures.
Root compared the moved orientation kernel and decode/orient/EXIF functions
byte-for-byte with their previous source before compiling: both matched.
`codec_owner.hpp` holds the same unique TurboJPEG/profile allocation owners;
the diagnostic pointer is now explicitly const. Decoder limits/color algorithms
are unchanged. The independent research static library has no install rule and
is not linked into File Manager, GUI.Forms or the Orchestrator daemon.

`file_manager_jpeg_experiment` retains fixture generation, comparison, WIC and
color/orientation tests. Its new `--emit-encoded N` and `--emit-color-encoded N`
modes produce a framed generated JPEG instead of decoding it. Existing direct
frame modes remain controls. `file_manager_jpeg_decoder` accepts no arguments,
owns one input buffer, calls the shared bounded decoder, then writes one raster
frame with the inert test ticket 7/11. Its entry point performs no fixture
generation or encoding. Linked third-party code is not claimed stripped of all
unused encoder routines.

## Input framing and failure

The experimental input is exactly 16 header bytes: eight ASCII bytes `FMJPEG01`,
followed by unsigned little-endian 64-bit byte length. Admit lengths 1 through
16 MiB only, validate before conversion/allocation, read exactly that many bytes
into one owned vector, then require actual EOF. No native layout, source identity,
filesystem grant, authentication or production request ticket crosses this input.

Invalid magic/length, short header/body, read error or trailing bytes fails before
decoding. Codec failure emits no raster. Diagnostics use stderr and exit status 1;
unexpected command arguments return 2. The result writer may fail after partial
output, so host process-status/extent checks remain required. The reader blocks
on input and final EOF; bounded elapsed time and cancellation require the future
host. An encoded length bound alone does not prevent a stalled sender.

After source receipt, input bytes remain owned through decoding and frame write.
There is no per-read vector growth, retained external borrow or image publication
from a failed call. Decoder scratch, ICC intermediates, output, input and transport
copies still need combined resource accounting. This separation makes a decoder-
only measurement possible; it does not itself measure or enforce a process cap.

## Local evidence

**MEASURED Windows Shadow:** GCC 16.2.0 Release, one compiler job. Existing three
JPEG/EXIF/ICC/WIC tests pass (1.97 seconds). All sixteen separate
generator → decoder → Rust-consumer streams pass: baseline/plain and progressive/
linear-ICC, orientations 1–8. The direct and separate baseline result frames are
byte-identical. Nine input refusals emit zero stdout bytes: empty, short header,
wrong magic, zero length, over-limit length, maximum u64, short body, trailing
byte and invalid JPEG. A fresh decoder after these failures matches the direct
reference again. This is fresh-process recovery, not in-process decoder reuse.

`verify_decoder_input.py` invokes fixed test binaries without a shell, uses
generated bytes, drains both output pipes and applies a 15-second subprocess
timeout. Its post-collection output-length check is an assertion, not a hard
output-memory limiter. Native CI runs this alongside all sixteen direct controls
and all sixteen separated cases. The 18-file C++ spelling scan passes; functional
checks and spelling alone do not establish full house-style compliance.
