## What this selects

- **Installation is allowed to become a place.** A serious installer may own
  the full visual field, sustain a panoramic fresco, use a large non-control
  illustration region, and culminate in an explicit completion ceremony.
- **Ceremony must remain technically honest.** Component names, current work,
  stable stage geometry, and an optional technical trace survive inside the
  illustrated world. A list of concrete components is more useful than a large
  generic percentage.
- **Ambient motion is preferable to navigational choreography.** Slow background
  life, a single restrained flourish, and one local activity object are viable.
  Curved eye-guidance, spatial stage movement, and crossfade/scale transitions
  are rejected. The interface changes state promptly and settles.
- **Bright optimism wins over dark editorial prestige.** Visual Studio blues,
  Office warmth, Watercolor fields, and compact Macromedia side art are accepted.
  Adobe CS2's black/white/red exhibition character and portfolio montage are
  rejected. Longhorn darkness is rejected even though a controlled sense of
  mystery remains desirable.
- **Custom appearance is not native-control imitation.** A setup shell may
  suppress native appearance provided control behavior remains conventional,
  fast, accessible, and predictable.
- **Richness may be geographically bounded.** Large blank space, stronger
  illustration, and creative-suite richness are tolerated in installation and
  rare ceremony, not in the daily file list.
- **A compact wizard remains legitimate.** Permanent illustrated side art and a
  small modal surface are preferred for short bounded operations; not every
  setup task deserves a full-screen world.

## Work-surface consequences

- Visual Studio's internal fresco/title region, colored identity band, native
  structured information surface, and dominant recent-project history are
  accepted references.
- Web-page composition, news/RSS, promotional/editorial video, and home-page
  abstraction are confirmed anti-models for the file manager.
- Tabs are rejected even for a temporary start surface (`C141`).
- Large Metro-style typography, flat color fields, and monochrome glyph
  replacement are anti-models. High-color material icons remain required.
- More polish never justifies slower startup or a heavier renderer.

## Progress grammar

The accepted combination is:

1. exact current phase or operation;
2. honest component or stage identity;
3. expandable technical trace;
4. a small bespoke indeterminate object where progress cannot be measured;
5. explicit completion state which may settle or linger briefly rather than
   vanishing mechanically.

`C013` prevents treating a generic quiet animation beside dense phase text as a
sufficient design. `C164` does permit a genuinely authored activity object.
`C064` remains open until a better Macromedia activity-vignette reference is
found.

- Watercolor's ambient field and title-bar fresco are primary beauty evidence;
  Modern.Forms itself is not an appearance target.
- DML-like authoring should be pleasant for SOL and describe the GUI, while the
  later GUI.Forms/ADR records remain authoritative for actual architecture.
- accessibility, IME, tooltips, and blind navigation are deliberate published
  semantics, not an accidental consequence of host-native controls.
- thumbnails are index-connected: an unindexed location does not receive live
  object thumbnails.
- recent locations appear as independently clickable breadcrumb stacks rather
  than a landing page.
- allocated folder size appears only once indexed: no badge at or below 1 MB;
  then round by 5 MB below 100 MB, 25 MB below 1000 MB, 100 MB between 1 GB and
  1 TB, and 100 GB at terabyte scale. The compact embossed object notation is
  the `1G`-style badge rule, not an exact metadata line.
- object hover may become richer to save inspection clicks.
- search remains within the folder subtree the user navigated to.
- File Manager stores its own view/sort/geometry knowledge, shows hidden files
  only when enabled, and may offer an option not to copy hidden files during a
  folder copy.
- the extended path instrument opens from the terminal breadcrumb action/open
  tail, not automatically.
- ordinary drag means move on the same volume; a different volume, application
  destination, or collision changes the operation path according to later
  platform/interaction rules.
- plugins contribute information, never controls or styles.
- Home-rooted and drive-rooted trees are honest modes; cloud-backed volumes are
  treated as volumes rather than branded navigation abstractions.
- Quick Access, This PC, Libraries, provider landing roots, and analogous shell
  abstractions remain excluded.
