# Visual cue inventory, 2000–2012

Status: pre-plan collection. No cue is accepted merely because it appears here.

## Verdict grammar

Each cue receives one verdict from the architect:

- **ACCEPT** — use as a positive design constraint;
- **ADAPT** — preserve the named quality, not the literal rendering;
- **REJECT** — actively avoid;
- **REFERENCE** — useful comparison material, not a target;
- **UNSEEN** — obtain a better screenshot or animation before judging.

Verdicts apply to atoms, never automatically to the complete source product.
Record the intended surface (`title`, `toolbar`, `tree`, `content`, `preview`,
`dialog`, `installer`, `motion`, `sound`) and intensity when relevant.

## Next collection rule

Add cues in batches of 25–50. A batch should mix strong expected positives,
likely negatives, and ambiguous rare references. Do not ask “do you like this
product?” Ask what to retain or reject about each named atom.
