# Native mockup translation negative result 001

Date: 2026-08-10

Status: **GIVEN owner verdict plus OBSERVED repository evidence; causes remain HYPOTHESIS**.

## Verdict

**GIVEN:** the latest dogfed native File Manager GUI.Forms demonstrations do
not look substantially similar to the HTML mockup. The work had begun to move
in that direction, but achieving each increment was a slow, tedious manual
grind.

This supersedes any optimistic reading of “measured partial” as visual parity.
The demoboard milestones prove many retained behaviors and public GUI.Forms
capabilities; they do not establish an effective visual-authoring pipeline.

The demoboard's own D4 and D5 evidence already states that GUI.Forms is not a
proven visual superset, that exact prototype raster matching remains open, and
that current captures are not frozen final visual design.

## What the native work did prove

The negative visual verdict does not erase the useful evidence. The native
demoboard proves substantial retained behavior: stable identities, shell bands,
split panes, tree/object collections, menus, property editing, path popup,
search correspondence, criteria modules, deterministic fixtures, public-package
consumption, headless traces, and cross-builds.

Those are GUI.Forms/DNA primitives Web.Forms can target. They are not an
efficient visual translation method by themselves.

## Visual and authoring gap

**OBSERVED at the capture level:** the native surfaces preserve broad topology
and content roles but materially diverge in typography, icon/object material,
density, control geometry, relief, gradients, seams, whitespace rhythm,
caption hierarchy, and the relationship among title/ribbon/chassis/paper
planes. The native result reads as a different, plainer style family.

**GIVEN owner assessment:** the manual path required too much bespoke iteration
for too little visual convergence.

**HYPOTHESIS:** the dominant failure is not inability of Skia or GUI.Forms to
draw the pixels. It is loss of the browser's compact computed-style/layout
description when humans manually reinterpret it as imperative control setup and
ad hoc painting. Repetition, style inheritance, geometry relationships, and
state variants cease to be one authored system and become many local C++ edits.

That hypothesis must be tested. It is not permission to assume a compiler can
reproduce all browser semantics accurately.

## Web.Forms falsification rule

Web.Forms succeeds only if it changes both outputs:

1. **Fidelity:** the same atlas slice is substantially closer under the named
   structural, geometric, material, and typography comparisons.
2. **Authoring economy:** ordinary visual changes remain localized in
   HTML/CSS/tokens and regenerate without bespoke C++ control/paint edits.

The first experiment records source lines touched, generated lines, hand-written
C++ extension lines, diagnostic count, elapsed authoring/reconciliation time,
and browser/native error by region. Existing demoboard history is the qualitative
baseline; no unrecorded labor estimate should be invented after the fact.

Reject or redesign the Web.Forms hypothesis if the Folder slice still requires
per-control native restyling, private GUI.Forms access, manual pixel correction
in generated code, or an unbounded list of CSS exceptions. A compiler that
recreates the same grind behind a new syntax has failed.
