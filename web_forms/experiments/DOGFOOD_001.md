# Web.Forms dogfood 001

Date: 2026-08-10

Status: **MEASURED parser/descriptor/component projections, complete native
GUI.Forms trees, and stable-ID browser/native fidelity comparison**.

## Claim under test

A useful initial HTML/CSS subset can express attractive single-control,
compound-widget, and standard-application specimens; Stage 1 can reject source
fail-closed and deterministically separate content, geometry, typography, and
material; Stage 2 can emit deterministic orthodox C++17 descriptor code.

Rejection criteria were acceptance of JavaScript, inline handlers, missing
addressable IDs, invalid parent identity, unknown properties/units, or
background material without an explicit surface owner; nondeterministic IR or
C++; forbidden generated C++ idioms; or C++17 compile failure.

## Fixtures

- `boards/controls/button/` — one command button with normal, hover, active,
  and focus-visible material.
- `boards/widgets/breadcrumb/` — path buttons, compiled `::after` chevrons, and
  three dense history rows.
- `boards/apps/standard_shell/` — title/menu/workspace/sidebar/content/status
  application composition with Sapphire and Parchment CSS generations over one
  HTML content tree.

The File Manager concept atlas supplied the visual vocabulary; these are new,
small bounded specimens rather than copied fragments.

## Full vision-board rejection

Stage 1 was also run unchanged against
`frontend/planning/visual/frontend-concept-atlas.html`. Rejection is expected:
the atlas is a review/simulation artifact, not compliant production source. The
first useful diagnostics identify inline SVG subtrees, review-only `data-state`/
`data-theme`/`data-style`, addressable buttons without stable IDs, inline style
attributes, camel-case IDs outside the stable grammar, and the later script
block. Unsupported SVG is now recovered as one rejected subtree rather than a
cascade of false closing-tag errors; diagnostics are capped at 100 per pass.
This is a deliberate structural boundary, not a claim that vector art is
useless: a later closed SVG resource can paint an already-laid-out icon box,
but its descendants cannot become controls or determine surrounding layout.
The breadcrumb chevrons remain box-relative `::after` decoration for precisely
this reason.

This result supports the intended authoring cycle: extract one visual/control
idea into a small compliant board, rather than weakening the profile until the
entire simulation happens to pass.

## GUI.Forms capability consequences

The union requires flex/grid layout, logical lengths, nested surface reveal,
rounded borders, multi-stop linear gradients, bounded shadows, transforms,
pseudo-decoration ownership, and finite hot/pressed/focus state records.

**OBSERVED:** GUI.Forms already has retained `SurfaceMaterial`, fill layers,
rounded geometry, shadows, `MaterialPanel`, paths, transforms, themes, and
display chunks. The first Web.Forms-driven enhancement adds bounded
pointer/count factories for gradient stops, fills, and shadows while retaining
GUI.Forms' existing owned containers internally. It also adds CSS-angle linear
geometry which derives endpoints from the current rectangular bounds. Focused
material tests prove retained ownership, invalid pointer/count rejection, exact
cardinal endpoints, and a measured 145-degree rectangular resolution.

The experimental Stage 2 material projection now consumes the manifest and
emits direct GUI.Forms calls for every base surface it can lower exactly. Its
button path composes nonconflicting hover and active deltas into GUI.Forms'
existing retained input state machine; it does not generate pointer handlers or
reinterpret CSS strings. Signed authored outline offsets cover both the outer
button focus ring and the breadcrumb's internal ring. The report retains the
qualification that unstyled disabled states use the authored base recipe.
GUI.Forms now retains focus-cue modality separately from actual focus: keyboard
and semantic navigation expose the cue, primary pointer focus hides it, and
programmatic focus preserves the current modality.

The layout projection lowers `display:flex` direction, wrapping,
main/cross alignment, logical gaps, padding, and numeric `flex`/`flex-grow`
relationships into `FlowLayoutPanel`. Focused GUI.Forms tests prove live-frame
centering, space-between, stretch, and ratio growth. The button board projects
2/2 flex containers, breadcrumb 4/4, and both standard-shell styles 11/11. The
same pass now lowers bounded border-box width/height/min/max/margins/padding,
overflow clipping intent, horizontal auto margins, grids, weighted fractional
tracks, fixed tracks, auto tracks, gaps, and deterministic cells.

GUI.Forms now also publishes an opt-in authored background layer on every
retained `Control`. The display pipeline records that layer before control
content and unions its shadow outsets with the control's own visual outsets.
A focused nested test proves a child without a layer reveals the parent, a
child with a layer becomes the nearest surface owner, and invalid replacement
fails atomically. This removes the need to wrap a layout control in a separate
material panel. Native tree Stage 2 applies the IR's owned/revealed edges to the
same typed controls which own layout and identity. A linked 38-node probe proves
that composition against GUI.Forms, including the shell and workspace grid.

The refined capability scan distinguishes outer from inset shadows and uniform
from side-specific borders. Bounds-relative CSS gradient angles were first
reported as unavailable, then promoted only after the new primitive and focused
test passed. Independent square edge borders followed the same path and now
cover the shell's top/right/bottom separators; rounded edge joins remain
refused. Inset identity is retained separately from outer shadows, recorded and
replayed over the fill, excluded from damage outsets, and rendered by Skia from
the complement of a live rounded inner box under owner clipping. The Skia smoke
test checks actual raster pixels: the inner edge darkens while the adjacent
pixel outside the rounded owner remains the untouched background.
Bounded `::before` and `::after` boxes lower into distinct owner paint layers;
a focused native ordering test places before-content edges, control text, and
after-content edges in that order, while generated-code coverage admits and
compiles both forms through the capability manifest.

The completed experimental tree has one typed member per explicit hierarchical
ID and retains `data-wf-command` mappings in its report. The first linked run
also preserved a useful negative result: GUI.Forms' default 3px control margin
reduced the nominal 210px sidebar to 204px. The generator now establishes CSS
initial zero margin/padding before authored box values, and the probe passes at
210px. That is direct evidence for compiling the nested landscape instead of
stacking stock defaults.

The pinned browser/native oracle now compares authored identity, structure,
state, element bounds/clips, typography and semantic materials. The File
Manager reference has zero material-mismatch nodes; remaining geometry and
typography deltas stay explicit for targeted follow-up. Rounded joins for
independently colored side borders remain conditional on a specimen actually
requiring them. Production API/ABI selection remains separate.

## Scope of inference

This experiment does not establish pixel-identical WYSIWYG,
cross-rasterizer text parity, complete accessibility, resource decoding,
virtual collections, general CSS coverage, performance of a large atlas, or
backward compatibility. It does establish a generated retained tree, real
GUI.Forms construction, nested logical geometry, semantic material equality,
and fail-closed capability composition without runtime source interpretation.
