# T-HISTORY-OCCUPANCY-1: rolling whole-descendant tuples and capacity

Status: **recurrence and recall PROVED; collision bounds conditional on the
declared uniform/independent family; E13 behavior MEASURED**.

## Whole-history address

For atom codes `a_0,...,a_(n-1)`, modulus `P`, and base `b`, define

```text
H(a) = sum_(i=0)^(n-1) a_i b^i mod P.
```

For deletion history `h`, let `D_h=H(delete_h(a))`. Coordinate `j` maps `D_h`
to one of `B_j` cells. The coupled key for that history is

```text
K_h = (cell_1(D_h), ..., cell_q(D_h)).
```

The source publishes `{K_h : 0<=h<n}`. Every key is generated by one complete
descendant and one history. There is no borrowing among partial certificate
witnesses or among address coordinates.

## One-pass recurrence

The first history is

```text
D_0 = sum_(i=1)^(n-1) a_i b^(i-1).
```

Moving deletion from `h` to `h+1` changes only power `b^h`:

```text
D_(h+1) = D_h + (a_h-a_(h+1)) b^h mod P.
```

Thus all history fingerprints for `q` coordinates require `O(qn)` atom work,
`q(n-1)` rolling updates, and no descendant-string construction. Coordinates
for one `h` must be emitted together before advancing `h`.

## Recall

If equal-length sources have a common one-deletion descendant `z`, each has a
history whose exact descendant is `z`. Every deterministic coordinate maps
both to the same tuple, so their tuple sets intersect.

If a shorter query is an exact deletion descendant of a longer source, its
full-sequence tuple is in the longer source's history set. Reversing source and
query gives the other length direction. The `n-1,n,n+1` plan therefore has
exact declared-relation recall. Projection collision can only add candidates.

## Why coupling matters

Let two unrelated sources expose at most `n_x,n_y` histories. Assume uniform
independent coordinates.

If each coordinate is accepted separately, a different history pair may
witness each coordinate. A union bound gives

```text
Pr[separable false candidate]
  <= product_j min(1, n_x n_y / B_j).
```

For equal `B`, this is `min(1,n_x n_y/B)^q` and is useless once each coordinate
saturates.

For coupled tuples, one history pair must collide in every coordinate. A union
bound over history pairs instead gives

```text
Pr[coupled false candidate]
  <= min(1, n_x n_y / product_j B_j).
```

Coupling removes the spurious exponent on the number of history pairs. With
`w=sum_j log2(B_j)` key bits, the ideal bound is `n_x n_y / 2^w`.

## Support law with a candidate pool

Let at most `M` unrelated records enter one length/profile partition and let
the desired expected hash excess per query be at most `tau`. A conditional
sufficient bound is

```text
M n_x n_y / product_j B_j <= tau,
```

or, for a binary tuple key,

```text
w >= log2(M n_x n_y / tau).
```

Maximum content length alone is insufficient; candidate-pool width is also
part of the hash contract. For a no-excess claim over `Q` queries with failure
probability at most `delta`, another union bound requires

```text
w >= log2(Q M n_x n_y / delta).
```

These are sufficient ideal-family bounds, not deterministic guarantees.

## Deterministic lower boundaries

If a source exposes `d` distinct history fingerprints, private tuple identity
requires `product_j B_j >= d`; otherwise two histories share a tuple. This is
only a within-source lower bound. Useful candidate capacity usually needs the
stronger quadratic-and-pool envelope above.

No finite projected tuple deterministically excludes unrelated collisions.
Exact stored records remain external authority.

## E13 instance

At name lengths 18--19 and 288 records/split, separable fixed support of 384
dense cells saturated. Coupled two-coordinate keys crossed from one observed
all-split false candidate at `2 x 256` cells (16 bits) to zero at `2 x 512`
(18 bits). The latter used about 45--48 sparse history memberships/record.

This crossing is **MEASURED**, not a theorem that 18 bits is generally enough.
It is consistent with the capacity law and identifies the next external-scale
variable: maximum same-partition record pool.

Indeed, `ldfioi` and `kbmedf` collide in both literal and folded two-by-512
tuple keys; both are structurally all-letter. The lifted sources `ldfioia` and
`kbmedfa` have no common exact deletion descendant but are accepted by all
three views. The current deterministic family is therefore known to fail at
this width even below the generated names' length.

## Boundary

The deterministic modular polynomials are candidate coordinates, not proven
random or cryptographic hashes. Modulus, bases, mixers, coordinate counts,
cell scales, observation profile, length envelope, and semantic-view
composition are configuration identity. Ranking and parent-engine ngram,
transposition, and exact comparison policy are outside this theorem.
