# Filename retrieval refinement 005: protected kernels, typed length plans, and real support charge

Status: **CANDIDATE experimental system with disjoint synthetic evidence;
production feature, rank, scale, and native-resource gates remain open**.

## Outcome

The filename channel now has a complete radius-one experimental path from exact
source scalars to verified candidates:

```text
three source-anchored atom views
  -> degree-two certificate histories
  -> coupled binary occupancy cells
  -> exact-length posting plans for n-1, n, n+1
  -> exact one-scan typed verifier
  -> external record anchor
```

No deletion descendant, occurrence set, edit matrix, or global cross-length
hash transport appears on the active path.

## Three different minima

T-PROTECTED-KERNEL-1 makes the row question exact. For a finite protected
difference set `D`, the semantic support is the minimum codimension of a binary
kernel disjoint from `D`. E11 attained the exact minimum of two rows on every
development view.

That did not make a useful index. The declared development tail gate first
passed at four rows, and every tested disjoint literal/fold difference became
visible only at six. The correct support ledger is therefore:

```text
d_semantic(D)   minimum rows preserving named directions
d_candidate(W) minimum rows passing candidate/verification tails on workload W
d_ambient(A)   rows completing the declared unseen/ambient attack family
```

E11 measured `(2,4,6)` on its generated objects. This is not a universal
constant. It is a proof that the three questions cannot be collapsed.

## Row construction and its failure

The compiler works in two stages:

1. greedily select functionals on `span(D)` until no protected difference is in
   the prefix kernel;
2. lift each functional into a support-balanced representative of its affine
   coset modulo `span(D)^perp`.

The coset lift preserves every development guarantee exactly. It is also the
only part able to touch genuinely unseen directions. The disjoint result showed
that four lifted rows still missed literal/fold edges and lost to the plain
balanced control on candidate tails.

The next construction should stop demanding that one row family do two jobs.
The stronger multi-address candidate is:

```text
guard address     minimum protected-kernel code
coverage address  independent ambient/minimax code
```

They should remain separately addressable and charged. Fusing guard and
coverage into one coset representative conceals which objective supplied a
candidate and makes development fit compete with unseen coverage. This
guard/coverage split is K-H48; it has not been measured.

## Exact-length plan

For query length `n`, radius one admits exactly three stored lengths:

| Stored length | Query construction | Stored posting |
|---:|---|---|
| `n+1` | one exact cell per certificate | descendant occupancy masks |
| `n` | occupied query cells, unioned per certificate | descendant occupancy masks |
| `n-1` | query descendant masks | exact target-position keys |

The last row is the previously missing reverse direction: the longer query
supplies source masks and the shorter stored record supplies exact keys. It
requires a reverse key family but no semantic transport between stored hashes.

E11 retained all generated substitution, transposition, insertion, deletion,
and case sources and all exact radius-one ambiguity parents. Wider edit budgets
should add declared source lengths rather than a global band metric until a
lineage transport theorem exists.

## Active loops

```text
BUILD PER RECORD AND EXACT LENGTH
ITERATE n source scalars                                      [one observation pass]
ITERATE 3 views x Q<=8 certificates x 3 offset states         [fixed radius one]
  GATHER 2 exact atom lanes                                   [unroll]
  PARITY d frozen rows                                        [word batch]
  SET coupled occupancy cell
ITERATE 3 views x Q reverse target keys                       [one cell each]

QUERY
ITERATE source lengths n-1,n,n+1                              [exactly three]
  ITERATE 3 views x Q certificates                            [bounded]
    ITERATE occupied query cells                              [bounded by 2^d]
      READ posting
  INTERSECT smallest predicate unions first                   [early exit]
ITERATE candidates                                            [measured tail]
  SCAN filename once with the typed radius-one verifier       [no O(n^2) matrix]
```

The remaining expensive iterative is posting-cell enumeration for same-length
and reverse queries. At depth four E11 read 51 lists p50 and 56 p95 for the
protected layout. A material next optimization is a block-local union codec or
precombined certificate block, but it belongs to the engine only after its
cache traces identify that loop as the bottleneck.

## Resource surface

The selected protected layout used 78.51 logical memberships and 51.16 hybrid
payload bytes per record across forward masks and reverse keys. Queries read
1.64 KB p50 and 2.00 KB p95 of posting payload before candidate verification.
These are concrete codec controls, not storage promises: address dictionaries,
segment framing, cache lines, durability, compaction, and deletion remain
absent.

Finer projection increased stored payload but shortened query lists. Posting
bytes and query bytes therefore moved in different directions. The system must
select support against total cost after a relevance gate, never bytes/object in
isolation.

## Confidence after E11

- **High:** the protected-kernel definition, two-row least obstruction, ambient
  coset freedom, three exact-length plans, and matrix-free radius-one verifier.
- **Medium on generated inputs:** radius-one candidate recall, bounded
  candidate tails at four to six rows, and the sparse/bitmap hybrid payload
  control.
- **Low:** the current projection beats the balanced control; it does not.
- **Low:** hard-decoy ranking, consented filename relevance, million-record
  scaling, cache behavior, update/compaction cost, and native tail latency.

## K1 boundary

This round makes the semantic adapter implementable but does not open K1. A
conservative experiment can use the balanced route as a control and the
protected route as separately reported evidence. K1 still requires:

1. an accepted filename/path feature policy rather than research Profile 001;
2. a consented, independently frozen relevance split;
3. selection between balanced, guard/coverage multi-address, and another
   projection without touching the evaluation split;
4. real length histograms and declared edit budgets;
5. native engine segment, cache, update, deletion, and verification tails.

E12 later tests the guard/coverage split, certificate specialization, typed
policy evidence, and liveness. Its corrections and changed direction are in
`FILENAME_SYSTEM_REFINEMENT_006.md`; in particular, separate stored guards are
not promoted merely because this document proposed them.
