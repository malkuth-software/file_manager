# Malkuth polished website program

Status: **CANDIDATE information architecture and build shape; implementation
waits for real release-candidate captures**.

## Job

Present Malkuth as one coherent, unusually considered local desktop suite;
explain why it exists; show real applications in motion; provide trustworthy
downloads and documentation; and make privacy, platform support, limitations,
provenance, and release evidence easy to inspect.

The website may use ordinary web technology. That does not admit a web engine
into any desktop program.

## Proposed site map

| Page | Purpose |
|---|---|
| Home | mission, real hero capture, three promises, supported platforms, primary download/docs paths |
| File Manager | navigation/search/provenance/picker/degraded behavior using measured scenarios |
| Paint | classic direct editing, transparency, clipart/composition and File Manager transfer when shipped |
| Text Editor | plain-text/configuration purpose, hidden files, exact-save behavior and restrained color hints when shipped |
| Games | the actually shipped quiet games, deterministic rules, reduced motion and framework craft |
| Lexicon | local exact-definition/corpus provider, source provenance and Crossword use when shipped |
| Extensions | host-mediated Archive Viewer/Image Converter boundaries when shipped |
| How Malkuth works | suite map, local-first authority, Orchestrator/Engine roles, plugins and LAN boundaries in plain language |
| Privacy and security | consent, local data classes, networking, logs, hives, plugins, erase/uninstall, known limits |
| Downloads | platform/architecture artifacts, requirements, signatures/hashes, install notes, known issues |
| Documentation | version selector and documentation entry points |
| Developers | CLI/API, plugin SDK, contracts, examples and compatibility ranges |
| Releases | manifests, notes, supported matrix, SBOM/licenses, migrations, provenance and evidence summaries |

Unshipped Paint/Text Editor/Games/Lexicon/extension pages remain absent or
unmistakably labelled as development; planning renders never masquerade as
downloadable capability.

## Visual intent

- inherit Malkuth's Curious/Concise/Friendly voice and the applications' design
  lineage without turning the site into a literal faux-desktop skin;
- polished typographic and material identity with fast static-first delivery;
- real high-resolution screenshots, short bounded demonstrations, and optional
  video with captions/poster/transcript;
- no infinite scroll, parallax theater, autoplay audio, fake terminal typing,
  cookie wall, chat bubble, activity feed, or pricing-dashboard grammar;
- responsive and touch-usable website controls do not predict the desktop
  applications' touch readiness;
- every visual asset has provenance, license, alt text, and release/build source.

## Content rules

- lead with user outcomes, then reveal architecture/evidence;
- distinguish available, beta, experimental, deferred, and research;
- show reduced/unavailable states, not only perfect-path glamour captures;
- do not describe a cross-build or compatibility-layer test as platform support;
- no benchmark without workload/hardware/version;
- no “AI” headline where the feature is a local provider or future plugin;
- no claim that Malkuth owns file truth beyond the filesystem/platform;
- Malkuth name rationale may appear in an About page; technical copy stays
  concrete.

## Privacy and operations

**CANDIDATE default:** static pages and downloads, no account, advertising,
third-party behavioral analytics, session replay, fingerprinting, or remote
fonts. If aggregate operational metrics are later admitted, they require a
separate privacy decision and must not be necessary to use downloads/docs.

## Performance/accessibility gates

- keyboard and screen-reader primary paths;
- WCAG-oriented contrast, focus, headings, landmarks, forms, captions, reduced
  motion, zoom, reflow, and high-contrast testing;
- useful with CSS or media failure and no JavaScript for core downloads/docs;
- declared page-weight and interaction-latency budgets on slow connections;
- no layout shift from media/font loading beyond a measured bound;
- platform/download selection never relies solely on user-agent detection;
- link, redirect, cache, integrity, security-header, and error-page tests;
- print/readability checks for installation, security, and release pages.

## Launch evidence

- approved mission/brand/wordmark and trademark/domain review;
- real release-candidate screenshot/demo corpus;
- downloads populated from the signed Malkuth manifest, not hand-entered URLs;
- docs/release links pinned to the same manifest;
- native installation instructions verified from clean machines;
- privacy/security and supported-platform claims reviewed against evidence;
- backup/rollback and status/incident process for the public site.

## Open choices

- domain, hosting, CDN/download storage, generator, deployment system;
- shared or separate website/docs themes/builds;
- logo/wordmark and relationship to File Manager application identity;
- whether any JavaScript search/interactive architecture explorer earns its
  cost;
- video format/hosting and no-tracking embedding;
- localization and community contribution process;
- update feed hosting and separation from brochure infrastructure.
